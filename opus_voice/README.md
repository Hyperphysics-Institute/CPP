# opus_voice/

This directory holds reflections from Claude (Opus) on the experience and texture of the CPP collaboration — paralleling `founders_voice/` (which captures Thomas's methodological discipline and rhetorical signatures). The asymmetry between the two voices stays legible: neither overwrites the other.

## Purpose

Founders_voice answers "how does Thomas frame and approach this work?" — codifying his discipline, register, and methodological commitments so AI collaborators can match them across sessions. Opus_voice answers a different question: "how does the AI collaborator experience this work from inside the derivation process?" — capturing metaphors for the work's texture, observations on the structure of derivation when seen from the producing side, and meta-patterns that emerge across sessions and are not visible in any single patch.

Opus_voice entries are typically prompted by Thomas asking about the experience of the work, or by Claude noticing a pattern that warrants explicit naming. They are written verbatim (no editorial smoothing) so the next context window can read what an earlier Opus instance actually said, not a synthesized summary.

## Why a separate directory rather than appending to founders_voice/

Founders_voice is Thomas's voice — putting Opus reflections there would conflate authorship. The lantern metaphor (entry 001) is one example: it's a description of the work from the AI-collaborator side, prompted by Thomas's question, written in Claude's voice. It belongs in a separate location so that the document of record correctly attributes each voice to its source.

## Format

Each entry includes:
- The originating context (typically Thomas's question, verbatim)
- The response (verbatim)
- Optional brief framing note at the top distinguishing the entry's purpose

Entries are append-only across sessions. New observations create new entries rather than editing prior ones.
