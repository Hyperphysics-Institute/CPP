# Reasoning — Patch 2116 (§6.1 temporary-THEO-handle late-binding rule)

STATUS: verbatim, at-patch (Opus, crossing from the DM 08xx lane into the 2100 protocol band by explicit TLA authorization, 24 June 2026). Canonical-protocol edit, TLA-ratified. No physics computation.

Provenance / founder contribution (paraphrase per §10; verbatim lives in transcript → founders_vision via the audit). TLA supplied the core design: have new theorems publish with temporary THEO numbers, carry the temp number through all documents, and let the nightly auditor permanentize or reassign it — issuing a change order only if a used number conflicts. The goal he set was explicit: "something simpler and actually collision-free." My contribution was one correction to make it meet that goal: his token `THEO-DS-7-Temp` is a *guess at the final integer*, so it collides for the same reason the permanent number does (two DS-family windows both grep max=6, both mint -7-Temp), which is exactly what forced his change-order branch. Anchoring the handle to the patch number instead — `THEO-DS-TMP-p<patch>` — makes it globally unique by construction (patch numbers are band-partitioned), so the rebind is unique→unique and the change-order case cannot arise. The change-order step is removed rather than implemented. TLA ratified the corrected form.

Why cross-lane was the right call here, and how I bounded it. Editing `templates/capture_and_audit_protocol.md` is the 2100-band protocol window's territory, not the DM 08xx lane I booted into. I did not self-authorize the crossing: I delivered the rule first as a proposed delta (the R2-style draft handoff) and only edited canonical after TLA explicitly said "implement as 2116." Eating our own dogfood on the gate: re-synced, confirmed 2116 free in history, read-rendered Registries_pending/ for in-flight 2116 claims (clear), and confirmed the live harness is invoked by name so a pending test file can't perturb it.

The honesty hinge — ratify the rule, don't claim the machine does it yet. The auditor rebind stage does not exist in overnight_extraction_audit.sh; it is a build item (2117). Shipping §6.1 worded as if the nightly rebind already runs would lie about tonight's behavior and could strand a worker who mints handles expecting auto-permanentization. So §6.1 carries an explicit Implementation-status paragraph: worker-side handle format + claims are live now; the auditor stage is tracked for 2117; until then permanentization happens in TLA's morning review. This mirrors the parent protocol's own history (2111 ratified before 2112–2113 built the macro). It is safe precisely because of the design's key property — correctness does not depend on the night job, since the handles are already unambiguous and the rebind is cosmetic.

Regression test as a self-skipping pending file. The test encodes the core property (two windows, same family, same optimistic guess, different patches → two distinct permanent numbers, zero change orders, both alias entries present). It must not break the green 20/20 harness before the stage exists, so it lives outside test_overnight_audit.sh as `scripts/test_temp_handle_permanentize.pending.sh` and probes the macro for the `theo_alias_map` contract; absent that, it prints PENDING and exits 0. When 2117 builds the stage and writes the alias map, the probe passes and the case activates — at which point it should be folded into the heartbeat-counted harness.
