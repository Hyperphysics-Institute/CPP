## Decisions made building the package (the non-trivial choices)

1. **What to put under review.** Two halves, mirrored from the paper: Part A (3-for-3
   compatibility, structural) and Part B (the derived log class + the cutoff identification +
   two regimes). The spine §2 is the paper's argument compressed; guardrails §3 carry the
   deflation (bare compatibility near-automatic; not falsifiable; no THEO; C open).

2. **The core test handed to the panel (the thing most likely to flip a verdict).** "Is this
   just standard QFT plus a renamed cutoff, with no framework-specific content?" Stated
   explicitly in §6 (Sonnet steer) and §8 (SHIP verdict). This is the honest failure mode: the
   whole CPP-specific content reduces to identifying RGS's formal cutoff with ω_P=1/t_P, and a
   fair reviewer should pressure-test whether that is substance or relabelling. Surfacing it
   rather than hiding it is the point.

3. **Triage order.** T1 compatibility map (highest stakes — if the mappings are post-hoc
   relabelling, Part A collapses); T2 the derived divergence class (is it derived from the RGS
   kernel or merely consistent with their prose?); T3 the cutoff identification + two regimes
   (the equivocation risk, and whether the two-regime split correctly deflates v0.1's
   over-claim); T4 honesty/scope (new domain folder for a compatibility result? NO-THEO?).

4. **Verify code = stdlib mirror.** The repo script `scripts/1701_divergence_class.py` uses
   numpy; the embedded §7 code is a `math`-only mirror so any reviewer reaches SCRIPT-EXECUTED
   with zero dependencies (the Patch-0656 lesson: a reviewer cannot script-execute from a
   filename reference). Verified identical numbers (L=63.25, gradual bound 1.43 at T=1e-14,
   gap 27.5 orders).

5. **Delivery = inline-default (CONV-001 / dispatch §3b).** External reviewers cannot fetch the
   private-repo raw URL; the inline single block is authoritative. Raw URL kept as provenance only.
