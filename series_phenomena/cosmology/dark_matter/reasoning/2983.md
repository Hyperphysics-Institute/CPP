# Reasoning fragment — Patch 2983 (W-4 execution instrument: campaign driver + gated analysis)

The benchmark forced the central decision: ~2.7 s/Moment at 937 CPs means ~16 min per standard leg and ~550 CPU-hours for the full 1280-leg campaign — two orders beyond any session budget. But the campaign is embarrassingly parallel (every leg independent) and the founder's desktop runs continuously, so the execution becomes a founder mechanical action under PD-006: an overnight-scale multi-core run. The driver is built for exactly that: leg-atomic (each finished leg is one JSON, written atomically, skipped on restart), freely stoppable, workers configurable, and it computes NO statistic across legs — the analysis lives in a separate script that mechanically refuses to run until all 1280 legs exist, which converts the prereg's "no interim looks" from a promise into a property of the tooling.

Two disclosures in the 2968 style. First, the prereg left two implementation constants to the driver, fixed here before any evidentiary leg runs: the seed convention (the committed 2907 EM-lane jitter — per-DP separation ± 0.05, seeded) and the pair-matched control window (both legs 240 Moments; MEAS-1's 144-Moment control was a standalone calibration leg, but paired subtraction needs matched windows — this is the pair-matching reading of the frozen "2968 windows" clause, stated rather than slipped). Second, the leg-atomic design makes the prereg's checkpoint-resume audit trivially satisfied (a leg either completed in one process or doesn't exist), disclosed in the analysis header.

The smoke test validates the two things that must be true before the founder burns two days of compute: the engine path runs end-to-end from this driver, and the same seed reproduces the identical sea bit-for-bit — the pairing guarantee the whole variance-cancellation design rests on. Nothing evidentiary was touched; the smoke never writes to the data directory.
