# Reasoning — Patch 2759 (REACH-AUDIT-2714 execution: census + exposure table)

**STATUS: verbatim, at-patch.**

The census had to survive its own false positives before it could be
the census of record. First run: two UNEXPECTED `newp` hits — the
census script itself (it names the token it greps for) and
`ps1_quark_mass_ladder_verifiable.py`, which for one alarming moment
looked like an eleventh sampler. Inspection: the hit is `\newpage`,
LaTeX in a docstring — the substring match was too loose. Fixed with
a word-boundary pattern and self-exclusion; the second run matches
the charter seed set exactly. The same lesson recurred on the
consumer side: an initial shell grep flagged `1.461` inside a DM-3
results JSON — held-paper contamination would have been the audit's
worst possible finding — but the unescaped `.` was matching an
arbitrary digit; the escaped search finds nothing. Both incidents go
in the record because they are exactly the class of error an audit
exists to not make: a census that cries wolf is as useless as one
that misses the wolf.

The substantive judgment calls, in the order they were made:

**Chronology as positive genealogy.** For headline items (c)–(h) the
clean classification rests on a two-legged argument: (i) the
supporting patches predate 2714, and code cannot be descended from a
defect that did not yet exist; (ii) no post-2714 support was ever
added — verified for (g) by the "79.5% not in scope" line every S4-X
record carries, and for (h) by grepping the packet brief itself.
Chronology alone would be absence-of-contamination; the second leg
makes it positive. The charter's CLEAN bar is met.

**The suspicion confirmed — and why the classification is RERUN, not
WITHDRAWN.** For (a) and (b) the trace went exactly where the 2758
pre-registration feared: every measured leg of the "septuple" is a
2714-lineage chain, and the one clean comparator (N = 80) shows the
defect suppressing undriven fluctuations by the same ~20–25% the
finding attributes to the Sea. It is tempting to withdraw the finding
outright — but that would itself be a verdict moved by argument. The
honest state is: the measurement is void, the QUESTION is open, and
the campaign still needs the answer (PR1/PR2/PR5 all read it). Hence
CONTAMINATED-RERUN, with the original frozen criteria re-applied to
clean data. If a real suppression exists, the clean chains will show
it; if the whole signal was the bug, the clean chains will show that
— either way same-font.

**The FA-SG-R1 correction.** Tracing (h) exposed an over-scoping in
my own previous turn: I had told Thomas the FA-SG-R1 paste queued
behind the audit "per the economy rule." Re-reading 2757 and 2756 §6,
the economy bundle is the S4-X packet; the FA-SG-R1 packet is a
separate CONV-001 cycle that was already paste-ready and was never
named inside the bundle. The audit's clean confirmation removes any
remaining reason to hold it. Stated as a correction in the table
(§3(h)) rather than silently adjusted — the record should show the
scoping error, who made it, and what fixed it.

**RA-2, not RA-3.** Every genealogy resolved from committed artifacts
— the arc's own discipline (records citing their data sources per
CONV-003) is what made the trace mechanical. RA-3's founder-routing
clause never fires; nothing in this audit requires a physics ruling.
The one structural gift: zero registry exposure. The S4-X arc never
promoted a number into `predictions.md` or a frontier sector before
the anomaly died — the hold-everything-behind-the-audit reflex, plus
the release banners, meant the blast radius stayed inside the lane's
own records. The annotation clause satisfies vacuously, which is the
best possible way to satisfy it.

**X5-FE.** WITHDRAWN rather than RERUN because its discriminant role
no longer exists — B-CHECK-80B answered the question X5-FE was built
for, at a size where the answer is dispositive. Re-running a
superseded discriminant would be ceremony, which the review-economy
ruling forbids.
