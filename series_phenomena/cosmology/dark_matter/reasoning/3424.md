# Reasoning fragment — Patch 3424 (untrack a false gate certificate)

Patch 3180 committed
`data/beta_ladder_1b/duplicates_1b_verified.json` carrying
`status: INCOMPLETE`. It was not a result. It was the artifact of
exercising the analyze-refusal guard inside a container that had no
evidentiary legs, swept in by `git add -A`. My error at 3180.

Why it is worth its own patch rather than a silent deletion: a
gate-certificate file sitting in the corpus and reading INCOMPLETE is
worse than no file at all. Every other certificate in this arc means
something — PASS means sixteen (or four) duplicate pairs were compared
element-exact and matched. A future reader, or a future instance of me,
finding this path in the tree has every reason to treat it as a real
gate record for Phase 1B. It would have said the opposite of the truth:
the real Phase 1B gate PASSED, on duplicates computed after a host crash.

It surfaced because it blocked the founder's `git pull --rebase` — the
tracked stub had been overwritten locally by the genuine PASS result, so
git reported a modified file. A defect that announces itself by
obstructing the founder is a lucky defect; the same file could have sat
unnoticed for months.

Fix: untrack it, and .gitignore the generated artifacts (leg trees, gate
certificates, redirect captures) so the class cannot recur. Gate status
continues to live where it belongs — in the verdict records, which are
prose and get read. Note this does NOT establish a corpus-wide policy
against committing data: MEAS-2 and MEAS-3 deliberately committed their
data directories. It scopes only the beta-ladder's generated files.
