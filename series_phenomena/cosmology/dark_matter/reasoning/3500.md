# Reasoning fragment — Patch 3500 (lane numbering split + mechanical gate)

Prompted by the founder asking two questions: whether I had overwritten
the frontier while capturing this session, and whether DM should move
out of the block DE is also writing into.

ON THE FIRST — CHECKED, NOT ASSERTED. Every frontier write this session
used prepend-and-prefix: insert a new `**Last updated:**` line above the
existing one, prefix the old with `Earlier `. The diffstat proves it —
`git show --numstat` reports exactly `2 insertions, 1 deletion` on
research_frontier.md for 3199, matching 3189, 3190, 3191, 3193, 3195,
3196 and 3198 from other windows. The GR lane's 3343 header is still
present. Nothing was lost. That rule is now written down in
id_block_registry.md with its verification test ("if a diff on
research_frontier.md shows more than one deleted line, the write is
wrong"), because the convention was being followed by imitation rather
than by rule, and imitation fails silently.

ON THE SECOND — THE FOUNDER IS RIGHT, AND I AM THE PROXIMATE CAUSE.
DMDE.md's pointer read `Next patch (DM/DE): 3424`. I claimed 3424 for the
untrack patch and 3425 for the handover, then advanced the shared pointer
to 3425 — editing, on the DE lane's behalf, a reservation that was not
mine. No content was lost because the DE window had not yet written, but
that is luck, not process. A shared number space with a single pointer
across two independent context windows has no mechanism to prevent this;
it only has care, and care is what failed.

Fix has three parts, and the third is the one that matters:
  1. DM to 3500-3599; DE keeps 3400-3499; pointers split per lane.
  2. id_block_registry.md as the canonical table, with the rule that a
     `Next patch` pointer is a RESERVATION, not a suggestion.
  3. code/next_id.py — mechanical, because the three collisions this
     programme has had (3168/3169; 3175 against a 3344 pointer; today's
     3424/3425) were all committed by someone who had looked. It greps
     git log bodies, research_frontier.md, frontier_sectors/*.md AND
     handovers/*.md, since 3424's reservation lived only in a sector file
     and my by-eye grep of the commit log never saw it. It recommends
     highest-used + 1 rather than the lowest gap: a gap is often a
     reservation whose pointer we failed to parse, and inserting into the
     past makes history read wrongly.

Scope: governance only, no physics. Registered as the first patch of the
DM block so the block's opening act is the rule that governs it.
