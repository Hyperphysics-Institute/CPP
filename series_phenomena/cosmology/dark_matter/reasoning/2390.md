# Reasoning — Patch 2390 (2381 V5 cache-pin repair, pre-flight for SS43-Q1)

STATUS: verbatim, at-patch (Opus, DM lane, 9 July 2026, session opened on
DM-WARM-2389).

The SS43-Q1 launch's V1 (run the 2381/2382/2383 batteries by subprocess) failed on
first execution: 2381 exit 1, cascading to 2382 and 2383 whose own V1-underneath
checks pin 2381's exit code. Root cause: 2381's V5 asserts the unit cache at
EXACTLY 336 keys, but the committed cache is 360 — 2383's above-floor extension
was committed WITH the DM-WARM-2389 handover set, whose text itself names "360
keys". So the 2389 contract's V1 was unsatisfiable as written: the handover
committed a state that falsifies the battery the same handover demands green.
Machinery-catches-author, fourth of the arc.

The repair preserves the check's protective content and removes only the
staleness-by-construction. What V5 actually protects: (i) the FULL floor ε_th
bracket — 32 N × 2 signs × 5 ε_th at S_c = 0.012 = 320 keys — which every
floor-robustness read (2383's ρ*_min rows, Q1's bracket report) depends on;
(ii) valid 13-bin schema for every key; (iii) no silent shrinkage. The repaired
form asserts exactly those three: floor set membership reconstructed explicitly,
schema over all keys, count monotone ≥ 336. Exact-count and exact-S_c-grid pins
are dropped BECAUSE the cache's registered growth mode (above-floor and fine-wall
extension points at ε_th = 1) is append-only by contract — an exact pin would be
re-falsified by Q1 itself within the hour.

No verdict content touched; the three batteries rerun green (6/6, 7/7, 5/5, all
exit 0) before Q1 proceeds. The fine wall takes 2391.
