## §2 — The worker's pre-registered test was wrong, and why

At 2859 the worker froze this test: *if PR1–PR7 were first registered
after Patch 2684, B7's "promotion" cannot refer to them, and R-1 holds
by chronology.*

**The test ran and returned R-1.** PR1–PR7's defining file was added at
Patch 2804 (26 July); the string "PR7" first appears in the repository
at Patch 2804; B7 is Patch 2684 (20 July). Chronologically airtight.

**And the conclusion was false.** The test measured **naming**, not
**content**. B7 named "**promotion**" as an *open placeholder step*.
The content of that step was frozen 42 patches later at the 2726
adjudication. **A gate's later definition does not remove it from an
earlier chain that named it as pending.** Absence of the label is not
absence of the gate — and the worker knew B7 said "promotion," having
quoted that exact word at 2859 §4, and still built a test that could
only detect the label.

**A pre-registered test is not a correct test.** Freezing it in advance
prevents outcome-shopping; it does not prevent asking the wrong
question. This is the third distinct failure mode registered in one
session, and unlike the other two it survived the discipline designed
to catch it.
