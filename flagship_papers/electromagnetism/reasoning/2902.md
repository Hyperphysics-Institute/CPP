# Reasoning fragment — Patch 2902 (mobile-Sea engine: prereg first, drive unread)

**STATUS: contemporaneous. Prereg at
`sketches/mobile_sea_moving_source_prereg.md`; engine at
`code/2902_mobile_sea_engine.py`; validations run at commit time, dressed
measurement deliberately NOT run.**

The design decision that took the longest was what NOT to build on. The
obvious move was to extend `2802_automaton2_engine.py` — it carried the
ratified G1 gate. But the arc's own record rules it out: 2887 proved that
engine diffusive (the translation-invariance reduction discards
propagation direction), 2888 declared the LW question ill-posed for it,
and 2893 found that every neighbour-relay engine of the arc was testing a
model the c05 spec does not describe. The spec is shell broadcast:
ballistic, geometric 1/4pi r^2, retarded because the shell takes time to
grow. 2895 verified exactly that structure for travelling DI-bits. So
the engine is pairwise retarded shell-broadcast — deterministic, no
Monte Carlo bits, the retarded condition solved exactly per pair by
bisection on stored trajectories. This is "read the spec, not the
committed engine," applied at the moment it costs something.

The founder's two rulings did real design work. One rule for all CPs
meant pairs move per-CP with no bond term anywhere — and V2 then had to
show binding EMERGING from reception alone, which it did: an isolated
pair oscillates between separations 0.4 and 0.6, period-2, bounded over
500 Moments. That is a ZBW-like bound state produced by nothing but the
primitive plus the step cap, and it is the engine's own existence proof
that "arc" behaviour needs no compliance rule. Emission-is-state-
independent meant no induced-response amplitude anywhere in the code —
which makes this engine structurally UNLIKE the 2884 toy (where the DP's
response amplitude tracked the received amplitude). The dressed drive
here can only come from geometric displacement of the pairs, i.e. from
the founder's arcs themselves. If the toy and the engine end up agreeing
about cancellation, it will be for the right reason.

Order of operations, stated plainly because it is the point: the bands
went into the prereg, the prereg and the engine go into the same commit,
and the dressed drive has not been read. V4 runs the moving-source
configuration and reports only that nothing blows up. I know the
temptation from two days ago — the eps* = 1/|k| affair — and the cheap
defence is to make the incriminating measurement impossible to have seen.
The one number I did allow myself is the beta = 0 floor, F0 = 1.7e-3
over a 30-Moment window with per-Moment std 1.1e-2, because the Q
criterion needs it and it carries no directional information (it is a
symmetry violation plus ZBW chatter). It taught me something practical:
the floor is averaging-limited, so F0 must be measured with the SAME
window as each production run or the Q comparison is rigged in my
favour. Noted for the execution patch.

What worries me, recorded in advance: (1) the drive may sit under the
ZBW chatter at feasible window lengths — if Q fails, the honest verdict
is INCONCLUSIVE and the fix is longer windows, not wider bands; (2) the
cylinder is small (rho_max = 8) and 2901 showed the near field dominates
the cancellation question, so the section-5 cutoff variations are not
formalities — they are where a fake verdict would come from; (3) the
source is charge +1 against a neutral Sea, so the mean SSV_abs at the
source (1.07 in V3) is mostly its near pairs, and the domain-dependence
of the denominator is why the prereg makes raw SSV_net,x the primary
observable. Execution next patch, against these bands, exactly as
frozen.
