## §3 Computational geometric verification

Three new computational checks added to the verification script for Q1'.A:

(a) **First-shell triangles are 600-cell faces.** For every 600-cell vertex's first-shell icosahedron (12 edge-neighbors), all 20 triangular faces of the icosahedron are 600-cell faces. Verified across all 120 host vertices; total 2400 (host, face) pairs.

(b) **Each 600-cell face has exactly 2 host vertices.** The host vertices of a face are the common neighbors of its 3 face-vertices in the 600-cell edge graph (= vertices outside the face that are adjacent to all 3 face-vertices). Computed for all 1200 faces; the distribution is completely degenerate at 2 (Counter({2: 1200})). No face has 1 host or 3 hosts; every face has exactly 2.

(c) **The K3 face cosine identity.** For a host vertex $v_0$ and a triangular face $\{v_a, v_b, v_c\}$ in $v_0$'s first-shell icosahedron, the cosine between $v_0$ and the face centroid direction is exactly $\sqrt{3}/2 \approx 0.866$ ($30°$ off-axis). The closed-form derivation: $v_0 \cdot v_i = \phi/2$ (edge dot product); $v_0 \cdot (v_a + v_b + v_c) = 3\phi/2$; $\|v_a + v_b + v_c\|^2 = 3 + 3\phi$; therefore $v_0 \cdot \hat{c} = (3\phi/2)/\sqrt{3+3\phi} = \sqrt{3\phi^2/(4(1+\phi))} = \sqrt{3/4} = \sqrt{3}/2$ using $\phi^2 = \phi + 1$. Verified numerically.

All checks pass; the verification script now runs both Patch 0418's Finding C-W36 checks AND Patch 0419's Q1'.A checks end-to-end in < 30 seconds.

## §4 The face-host count error and correction

During §11.2 drafting I initially produced a confused combinatorial claim: that each 600-cell face is a first-shell triangle of "3 of its 3 vertex hosts" (a self-contradictory phrasing) or alternatively "2 of its 3 vertex hosts" (treating the face's own vertices as host candidates). Both framings were wrong.

The error: a vertex is not in its own first shell (no self-loops in the 600-cell edge graph), so the face's own 3 vertices are NOT host candidates. The hosts of a face are vertices *outside* the face that are common neighbors of all 3 face-vertices.

After the computational verification surfaced the clean fact (each face has exactly 2 hosts, both outside the face), I corrected §11.2, §11.3 face-aligned bullet, and §11.6 sub-note via three str_replace edits before committing. The error and its correction are recorded here for transparency. The underlying Q1'.A and Q1' resolution is unchanged — face-aligned still has host ambiguity (now precisely "2 candidate hosts" rather than the confused "2 of 3" framing) and vertex-aligned still uniquely identifies the host via $\hat{n}$.
