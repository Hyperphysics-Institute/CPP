# 4105 — sibling-gate audit: continuity_gate was not watching the live block (discharges TODO-4102-NEXTID)

**Lane:** EW. **Trigger:** TODO-4102-NEXTID, opened at 4102 after `next_id.py` was found
blind to this lane's bare-numbered commit subjects and recommended the already-pushed 4101.
The residual asked whether the sibling gates carried the same assumption.

## What the audit found

**They do not carry the leading-zero assumption.** `continuity_gate.py` matches
`\s*(?:Patch\s+)?(\d{3,4})[a-z]?\b`, which reads `4101 F3 DERIVED …`, `0935 EVAL …` and
`Patch 3406 …` alike — verified against all four forms. `absence_gate.py`,
`deferral_gate.py` and `encoding_gate.py` parse no patch IDs at all; they scan commit-message
content and files. So the 4102 defect was confined to `next_id.py`, as hoped.

**But the audit found a different and worse defect in the same file.**
`continuity_gate.py`'s `BLOCKS` still read `'ew':(4000,4099)`. The live EW block has been
4100–4199 since Patch 4100. So the gate whose entire purpose is detecting a silently-missing
patch **was not watching the range that every patch from 4100 onward was written into** —
4100 through 4104 were outside its coverage. A mid-block gap in this session would not have
been reported.

## Root cause — the rule, not the file

Registry Rule 6 said: *"A block-opening patch updates `code/next_id.py`'s `BLOCKS` table in
the same commit."* It names **one file**. It was written at Patch 3807; `continuity_gate.py`
did not exist until Patch 4029. The rule never grew to cover the second table, so my Patch
4100 satisfied Rule 6 exactly as written and still left a gate stale.

This is the **fourth Rule-6 lag on record** (3700, 3800, 3900 in `next_id.py`) and the first
outside `next_id.py`. Fixing only the instance would guarantee a fifth on whatever gate is
written next, so Rule 6 is generalised to *every gate carrying a block table*, naming both
current ones.

## A second, quieter defect in my own 4100

Patch 4100 **replaced** `next_id.py`'s `'ew'` entry rather than adding beside it, dropping
4000–4099 out of the gate's view entirely. The established convention retains exhausted
blocks (`eu-3800`, `gr-3600`, `gr-3300`, `legacy-cosmology`) precisely so `--all` reports them
EXHAUSTED. An exhausted block invisible to the gate is one a later lane can be told is free.
Restored as `ew-4000`, and the retention requirement written into Rule 6.

## Verification

- `next_id.py --all`: ew 4100–4199, 5 used, next free 4105; ew-4000 4000–4099 EXHAUSTED.
- `continuity_gate.py`: ew 4100–4199, 5 used, 4100..4104 **contiguous**; ew-4000 reports the
  known 4065/4067 gaps.
