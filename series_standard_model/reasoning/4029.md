# Reasoning — Patch 4029 (building the gate found a hole in the gate we already had)

**STATUS: verbatim, at patch.**

## Why here

4028 ended with a named failure mode and no fix: *a patch that silently fails to apply is the one failure
mode this workflow has no gate for.* Naming and handing on is the move PD-008 exists to stop, and I have
now done it twice in one arc (4023, and the 4025 fix). So: build it.

## What the gate can and cannot do

**`code/continuity_gate.py`** compares local against origin **by patch number, not by SHA**. That detail
was learned the hard way: the first version compared SHAs and reported *every* applied patch as missing,
because `git am` on the founder's machine rewrites them. A gate whose first run is a false alarm is a gate
that gets switched off, so it was fixed before shipping.

**Gaps are reported, not failed.** A gap in a lane's run may be an unparsed reservation, and nothing inside
the repo distinguishes a reservation from a loss. Failing on them would make the gate noise.

**And the limit is in the file, not just in this fragment:** a cleanly-missing **tail** patch is not
detectable from inside. The missing patch is also the one that would have updated the registry and the
frontier header, so what remains is self-consistent at N−1. That half of the fix is procedural and has to
run on the founder's machine.

I would rather ship a gate that says clearly what it cannot see than one that implies coverage it does not
have.

## And then it found something

The scan flagged **3406 and 3407** as absent from the DE run. They are not absent — **one commit covers
both**, titled *"Patches 3406/3407: RES-W-1 …"*.

`next_id.py` matched `Patch(?:es)?\s+(\d{4})`. It handled the plural and then **captured the first id and
stopped.** So **3407 was registered nowhere and would have read as free.** Across the corpus, **21 ids**
were invisible to that pattern — *"Patches 0359, 0360, 0361, 0363"*, *"Patches 0314 / 0344"*, and similar.

That is a defect in the file the whole programme uses to avoid ID collisions, found by a gate built for a
different purpose entirely.

## Not oversold

**No lane's next-free changed.** DE goes 49 → 51 used, legacy-cosmology 99 → 100, and every next-free sits
where it sat. **The defect was real and had not yet bitten.**

The honest headline is the smaller one: *found before it bit*. I want that stated plainly, because the
larger framing was available — "averted a collision in the canonical ID gate" — and it would have been
wrong. What makes it worth having anyway is that the collision it could have caused is the exact shape the
registry's own Anomalies section records **three times**, each committed by someone who had looked.

## Gaps handed on, deliberately

**chir 0901, 0934** (0978 is already documented as superseded before push); **de 3427, 3428, 3437, 3447**;
**dm 3502**.

I did not investigate these and I am not calling them losses. A gap may be a reservation; this lane does
not own those blocks; and the owning lane can settle each in minutes with the evidence in hand, where I
would be guessing. That is a different thing from 4023's handing-on — there the question was mine and I
ducked it. Here the blocks are someone else's and the evidence travels.

No panel. No verdict moved.
