## Why the moves stayed pure (and where they didn't)

3230 is file moves plus identifier bookkeeping only. The one content-ish
edit — GR-1's ladder/bib/README updated to GR-1a–h with "(formerly cNN)"
tags — is part of the move by definition: the parent tracks its companions'
identities, and leaving GR-1 pointing at dead cNN numbers would ship a
freshly wrong paper. Everything else (each companion's internal "Companion
N" prose) rides its next natural version bump; rewriting shipped text inside
a move patch is how provenance gets muddied.

3231 carries one approved content addition per paper: the complementarity
notes. The founder explicitly approved cross-referencing near-duplicated
results this turn, and the note is the whole point of the ruling — shipping
the move without it would leave the public-reader duplication problem the
ruling exists to solve. Framing chosen: "two structural levels of the same
sector; neither supersedes the other" — deliberately symmetric, because
SS-1b/d are panel-reviewed and SM-11/12 are not, and an asymmetric framing
would either overclaim for the unreviewed papers or quietly demote them
before any panel has looked.

The founder reported the c22 .tex "lost." Full-history search (the
unshallowed clone earning its keep) says stronger: **no Spin III .tex ever
existed in this repository.** The c22 folder was born as README + development
notes + c10-labelled eigenvalue scripts/data/figures/notebook. The nearest
deleted relative, `SM_particle_spin_ZBW_derivation.tex` (589 lines, deleted
16 Mar 2026, commit 80381db9), is a Spin-I draft variant — recoverable from
`80381db9^` if the founder wants it, but it is not the missing paper.
Consequence: this is a rewrite-from-materials task, not a recovery task, and
the materials are good — the development notes contain the founder's spin
mechanism in his own words plus a prior Claude scrutiny pass, and the
eigenvalue computation already exists as script + data.

## Windows safety

All three patches generated with `--no-renames` (full-content, 2.5 MB for
3230) — not because case-only renames are present, but because rename-format
patches against space-named folders and a directory-named-.tex are exactly
the input class that has produced `git am` context failures on the founder's
machines before. Bytes are cheap; his recovery time is not.
