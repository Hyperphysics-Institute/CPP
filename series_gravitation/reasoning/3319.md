# Reasoning fragment — Patch 3319 (21 Aug 2026)

**Scope:** the founder asked whether a standing order exists to update
`osf_deposit_queue.md` when a paper changes. Audit answer: the order
existed only INSIDE the artifact ("Re-run after any patch," queue
header) — not in the OS — and it demonstrably did not fire: the queue
was last generated 18 Aug, BEFORE the gravitational arc's papers
landed at their current location, so the ENTIRE GR series (11 papers,
including the three CONV-030-amended ones) was absent from the 117-row
queue, and 12 rows still pointed at the retired SR-companion paths
(c05–c15, c20–c21).

## What was done

1. **Regenerated:** 117 → 122 papers; all 11 GR papers present at
   current versions; the 12 orphaned rows verified BEFORE acceptance —
   each is a relocation (c05→GR-1a … c13→GR-1h; c14/c15 → strong/SM;
   c20/c21 → the SPIN homes) and none carried irreplaceable owned data
   (no RESERVED_DOI / PREPRINT_ID / APPROVED; only derivable
   PARENT/RELATION/COMMUNITY defaults). Dropping them loses nothing.
2. **Generator fix (version_of):** the parser required "N.N" and took
   the MAX over the whole header — two defects at once: integer
   versions ("Version~3", legal in \date{}) parsed as "—", and a
   max() over header comments can report a FOREIGN version (GR-1a's
   header cites the parent SSV paper "Version~16"; integer support
   alone would have published GR-1a as v16). Fix: the \date{} line is
   authoritative when it carries a version; header-max is the
   fallback. GR-1a/GR-1d now report 3 and 3 correctly.
3. **GR-1b version reconciliation:** its \date said 3.2 (stale since
   the 3293/3294 era), header comments reached 3.5, the suite
   changelog 3.6 — three answers to "what version is this paper."
   \date reconciled to 3.6 (compile 0 errors). The date-first parser
   makes the \date line the single source of truth going forward.
4. **Standing order codified where it belongs:** §15 Step E gains a
   registry line — any session that touches a paper .tex re-runs the
   generator and commits queue+manifest in the closing patch, with
   the orphan warning VERIFIED (an orphan carrying a RESERVED_DOI or
   PREPRINT_ID means stop and remap by hand). The artifact-level
   header was necessary but insufficient: instructions inside
   generated files are read by people who already opened them; orders
   must live in the protocol the session-close audit walks.

## The general lesson

Same class as the 3309 gitignore finding: a correct instruction in
the wrong layer. "Re-run after any patch" was true, visible, and
never executed, because nothing in the close-out checklist pointed at
it. The fix is always the same move — put the order on the path the
audit actually walks.
