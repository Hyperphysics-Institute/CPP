# Reasoning — Patch 3293 (GR-1b V3.4: the figures had never rendered)

**Session 153, 20 Aug 2026. Verbatim at-patch capture.**

## How this was found

Not by looking for it. The session opened on W-D, and the first step of
editing any `.tex` is the baseline compile — run *before* touching the
file, so that any later failure is attributable to the edit rather than
to the environment (the discipline adopted at 3276). GR-1b's baseline
came back with three errors.

First reading: an artifact of my own setup. I had copied the `.tex` to
`/tmp` without its `figures/` directory, which would produce exactly
those errors. So I re-ran in place, expecting zero. Still three.

## What was actually wrong — two defects, compounding

1. **The figures exist only as SVG.** Patch 3274 (W-A2) created the
   three images this paper had always cited without possessing, and
   switched the `.tex` from the `svg` package to `graphicx` to drop the
   inkscape dependency. But `pdflatex` + `graphicx` cannot read SVG.
   Only `.svg` files are in the repository.
2. **No `\graphicspath`.** The `\includegraphics` calls name bare
   filenames (`fig1_lsp_metric.pdf`) while the assets live in
   `figures/`. Even with PDFs present, they would not have been found.

Either defect alone would have been enough. The consequence is that
**GR-1b has never rendered its figures** — not before W-A2 (no files at
all) and not after (wrong format, wrong path). It compiled with three
`pdftex.def` "file not found" errors and three draft-mode placeholder
boxes where the figures should be.

## The part I have to own

The Patch-3283 suite pass — mine — wrote the W-A2 entry in this paper's
changelog as "Drawn to the shipped captions (matplotlib → PDF,
committed)." The repository contained no PDFs. I reconstructed that
detail from the W-A2 narrative rather than from the file listing, and
stated it as fact in a changelog whose whole purpose is to be the
reliable record.

This is the failure mode the `STATUS: reconstructed` markers exist to
prevent, and the markers did not prevent it, because the error was not
in a section I flagged as uncertain — it was in a confident sentence
about a patch six days old. **Recorded as a process finding: when
reconstructing a patch's effect, check the artifacts, not the narrative.
A changelog entry asserting that files were committed is checkable with
`ls` in one second, and I did not run it.** The sentence is amended in
place rather than deleted, with the correction named, per anti-erasure.

Worth noting for the W-A2 record too: that pass reported "compile:
0 errors" for this paper. Either it was measured before the graphics
switch took effect, or the errors were not surfaced in whatever
check was run. I cannot tell which from here, and I am not going to
guess — but a compile gate that reports clean on a document rendering
three placeholder boxes is a gate worth examining.

## The fix, and why this is not W-D

Converted the three SVGs to PDF (cairosvg) and committed them alongside
the SVGs; added `\graphicspath{{figures/}}` after the `graphicx` load.
Nothing else touched.

Scoped as its own patch rather than folded into the W-D status-note pass
because it is a different defect class entirely — W-D corrects *claims*
that later work overtook, this repairs *rendering* that never worked.
Bundling them would have made both harder to review and would have put a
figure-asset commit inside a patch the founder expects to be prose-only.

## Verification, and the number that proves it

Compile gate before: 3 errors, 16 pages, 267 KB. After: **0 errors**,
14 pages, 532 KB.

The page count *falling* while the file size doubles is the confirmation
that matters, and it is worth stating why: draft-mode placeholder boxes
are drawn at the requested `width` with a default aspect that ran taller
than the real figures, so the document was two pages longer while
containing no images. A naive reading — "pages went down, something was
lost" — is exactly backwards. If the errors had merely been silenced
without the images arriving, the file size would not have doubled.

One `natbib` undefined-citation warning is **pre-existing**: it is in the
baseline log, unchanged by this patch. Not addressed here; flagged for a
future pass rather than silently absorbed into a patch about figures.

## What this suggests about the corpus

GR-1b is the only arc paper with figures, so this specific defect does
not generalize within the gravitation series. But the *shape* does: a
formatting pass reported success on a criterion it did not actually
measure, and a documentation pass then recorded that success as fact.
Both passes were mine or the programme's own, and neither was checked
against the artifacts until a third pass happened to run the compiler
for an unrelated reason. Flagged for the PPP program: any paper claiming
figures should have its rendering verified, not its `.tex` inspected.
