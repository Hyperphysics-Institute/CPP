# 0975 — reasoning fragment (verbatim, at-window; captured at 0980)

**Lane:** chirality (09xx). **Patch:** 0975, 14 Sep 2026. **Ships:** `code/deferral_gate.py` (two changes).
**Scope test:** ships a code change and records a finding ⇒ **not exempt**.

---

Booted into the lane, read bootup including §0.5, cloned full history, ran `next_id.py chir` against a fresh
fetch. Read the newest handover (session 228). The lane's own assessment was that it was empty of bounded
work, so the first real question was whether anything in the close was still open.

The Step audit in that handover listed Steps C and D as OWED and added that this was *"recorded here as the
explicit TODO Step H requires."* It was recorded in the handover only. D-9 — enacted at 0939, in that same
window — says a handover is a record and not a queue. So the item was a drop, and by the same rule that
window had written. Filed it as a todolist entry.

**Then I asserted a cause without testing it, and that is the substance of this patch.** I told the founder
the gate has a blind spot: a session-close patch touches `todolist.md` for other reasons, so the vocabulary
scan passes while the Step-H deferral never enters the queue. That is a mechanism, it is plausible, and it is
false. Running `deferral_gate.py c8a3c87f` takes one second and shows 0974 did not touch `todolist.md` at
all, so the mechanism I described never operated. D-1 says search for the mechanism before declaring a
failure; the equivalent here was to run the gate on the commit in question. I had the tool, I had the commit,
and I wrote the diagnosis first.

Two earlier diagnoses in the same exchange were also wrong, and the pattern is worth naming: my patch failed
to apply, and I said the founder had an unpushed local commit (it was pushed), then that 0975 had been
consumed (it had not — the other window renumbered itself to 0974a precisely to leave 0975 free, and the
registry said so). The actual cause was mundane: 0974a landed on origin between my boot fetch and my
`format-patch`, so my base had moved. **That is trap #1 of the handover I had just read**, and I walked into
it while quoting it back.

**What the gate actually did.** It scanned 0974, found 9 hits, and among them the exact line `**Steps C/D
(vignettes, verbatim narrative):** **OWED** — deferred for context budget`. It passed because `asserted` was
`"NOTHING-DEFERRED" in msg`, a bare substring test, and 0974's message contains the sentence *"deferral gate
run on every patch, all PASS or NOTHING-DEFERRED asserted in the log"* — a narrative report **about** the
gate, written in the same breath as the deferral. **0974 was not asserting the override. The gate supplied
one on its behalf, from a mention.**

0962 predicted this in writing: *"the gate fires on its own name, which will recur in any patch that cites
0939."* It recurred twelve patches later. And the first draft of this patch tripped it too — the token in my
own subject line silently granted me the override, which is how I found it.

**Two changes, and I considered and rejected a third.** (1) A mention is not an assertion: the token must
open a clause and introduce a reason with a dash or colon. (2) The override prints the hits it overrides,
because the author asserting it was the one person who never saw them — the trail was auditable only
afterwards, by someone else. **Rejected: making it a hard failure.** Surveyed the last 30 commits; three use
the token and 0962 and 0969 use it legitimately. Turning a properly-used escape hatch into a failure on the
strength of one misuse trades a rare false negative for routine false positives.

Regression-tested against the real commits rather than invented cases: 0962 (line-initial) and 0969 (after a
colon) still assert; 0974 now reads NOT asserted and **would have failed at the moment of the drop**, which
is the whole point.

**Residual, stated rather than hidden:** a quoted *example* of the token can still satisfy the clause test.
This narrows the hole; it does not close it. Closing it needs a structured trailer, which is a bigger change
than the evidence justifies. I reworded the docstring example so this patch would not self-assert, which is
a workaround and not a fix, and said so.

**D-9 needs no amendment.** The rule was right; its enforcement was porous. I did not touch bootup §0.5.
