## The load-bearing finding and why the chosen fix is right

Two of three reviewers (Copilot, ChatGPT) converged that "emergent" was used for two
epistemically different situations: (a) rows a registered theorem already derives, and
(b) rows merely *reducible in principle*, derivation owed. Per cross-reviewer
convergence weighting (2+ = load-bearing), this must be addressed.

Three candidate fixes were considered:

1. **Reclassify all derivation-owed emergent rows → unregistered** (Copilot's literal
   recommendation). Rejected as over-correction: it collapses the real distinction Grok
   defended — E12 (2I spinor reps, standard chiral math, obviously downstream of fixing
   n̂) is *not* epistemically the same as E19 (capture handedness, no candidate
   mechanism, consumed by everything). "Unregistered" per the audit's own definition is
   "neither axiomatized nor derived *and* no clear reduction" — the provisional rows
   *do* have a clear reduction target with no second primitive apparent. Collapsing
   loses signal and would mislead the downstream programme about which gaps are deep.

2. **Keep "emergent" as-is** (Grok's position). Rejected: it is the overclaim the
   2-reviewer convergence correctly flags. Calling a row "emergent" when no derivation
   exists asserts a reduction that has not been performed.

3. **Grade "emergent" into established / provisional** (adopted). This is the minimal
   change that satisfies both valid concerns: it stops claiming un-written derivations
   (Copilot/ChatGPT) while preserving the established/provisional/deep-gap distinction
   (Grok's valid point + the audit's own scope as a cataloging, not derivation,
   theorem). Established = a registered theorem carries it (E22/E23 via SD-CHIR-1/2;
   E24 via DSL-3; E25 via CONT). Provisional = reducible-in-principle, derivation owed,
   OPEN-CHIR target (E12,E13,E14,E15,E21,E26,E27).

The fix is label-only: no entry added or removed; the 27-entry inventory and every
entry's source/sense are untouched. This keeps v1.1 a calibration, not a re-derivation.
